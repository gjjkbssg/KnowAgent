# Agent vs 普通 RAG：人物多跳检索实证

## 结论

在这组实际运行的对照中，普通 RAG 只能回答 3 个子问题中的 1 个，Agent 回答了 3 个，并给出了两份对应来源。

这不是要证明“Agent 永远优于 RAG”，而是证明：当第二跳查询必须依赖第一跳产生的新实体时，Agent 的动态检索能力可以弥补固定一次检索的证据缺口。

## 实验数据

知识库：`[A/B演示] 人物多跳检索`

- 10 份虚构资料，所有人物、项目和指标均为合成数据。
- 1 份性能复盘记录业绩和姓名，但明确不记录后续任职。
- 1 份林晓人物访谈记录后续项目和导师，但不记录此前项目和性能数字。
- 8 份其他人物访谈作为“后来负责什么、导师是谁”这类语义相似干扰项。

测试问题：

> 谁把北辰项目端侧推理 P95 从 180ms 降到 70ms？这个人后来负责哪个项目，他的导师是谁？

标准答案：

1. 人物：林晓。
2. 后续项目：“萤火”离线语音助手。
3. 导师：周宁。

## A 组：普通 RAG，一次固定 Top-5

普通 RAG 只使用原始问题执行一次混合检索，真实 Top-5 为：

| 排名 | 文档 |
|---:|---|
| 1 | `08_许言人物访谈` |
| 2 | `07_唐可人物访谈` |
| 3 | `10_沈佳人物访谈` |
| 4 | `01_端侧推理性能复盘` |
| 5 | `06_周扬人物访谈` |

关键问题：`02_林晓人物访谈` 没有进入 Top-5。因此模型虽然能从性能复盘识别“林晓”，却拿不到林晓的后续项目和导师证据。

普通 RAG 的实际回答：

> 1. 将 P95 从 180ms 降到 70ms 的人是林晓，来源为 `01_端侧推理性能复盘`。
> 2. 后来负责哪个项目：无法确定。
> 3. 导师是谁：无法确定。

结果：`1/3` 个子问题有证据支持。

## B 组：Agent 动态多跳检索

Agent 的实际执行过程：

```text
原始问题
  ↓ 第一跳：按“北辰、P95、180ms、70ms”检索
01_端侧推理性能复盘
  ↓ 得到新实体：林晓
第二跳：knowledge_search("林晓", top_k=10)
  ↓
02_林晓人物访谈 排名第 1，score=0.8114
  ↓ 补充核验
knowledge_search("林晓 导师 mentor", top_k=10)
  ↓
02_林晓人物访谈 排名第 1，score=0.8622
  ↓
完整答案：林晓 → “萤火”离线语音助手 → 周宁
```

Agent 的最终回答引用了：

- `01_端侧推理性能复盘`：林晓将 P95 从 180ms 降到 70ms。
- `02_林晓人物访谈`：林晓后来负责“萤火”离线语音助手，职业早期导师为周宁。

结果：`3/3` 个子问题有证据支持。

## 为什么普通 RAG 没法在同一轮自然解决

原始问题没有出现“林晓”这个名字。只有读完第一份性能复盘后，系统才知道第二次应该搜索谁。

固定一次 RAG 的查询在检索前就已经确定，不能把中间得到的“林晓”变成新查询。由于库中存在 8 份包含“后来负责”和“导师”的相似人物资料，第一次 Top-5 被干扰项占据。

Agent 的优势恰好发生在这里：它可以把第一跳输出的实体作为第二跳输入。

## 面试现场 40 秒话术

> 我做了一组真实 A/B 对照。问题是：“谁把北辰项目 P95 从 180ms 降到 70ms？他后来负责什么项目，导师是谁？”原始问题里没有人物姓名。普通 RAG 一次 Top-5 找到了性能复盘，所以知道这个人是林晓，但林晓的人物访谈被八份相似人物资料挤出 Top-5，后两个问题只能回答无法确定。Agent 第一跳得到“林晓”后，主动发起第二次 `knowledge_search("林晓")`，人物访谈立即排到第一，于是补齐“萤火离线语音助手”和“周宁”。所以这里 Agent 强的不是生成能力，而是能利用中间结果改变下一步检索。

## 必须主动说明的公平性边界

- Agent 使用了更多检索和模型调用，因此延迟和成本高于一次 RAG。
- 如果扩大普通 RAG 的 Top-K，或者预先建立完善的实体图谱，它也可能找到第二份资料，但会注入更多干扰上下文。
- 简单单跳问题不应该使用 Agent；Agent 适合身份解析、多跳关系、故障归因和需要动态补证的问题。
- 本实验是可解释的合成案例，用于验证机制，不代表真实业务总体准确率。
